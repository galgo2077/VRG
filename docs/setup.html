01 / REQUIREMENTS & SOURCE

Start with the F4 tag.

Install Git, Rust + Cargo (1.92 or later) from the official Rust guide ↗ and the compiler/build tools required by your platform. On Void Linux, verify distribution package names before installing them.

$ git --version
$ rustc --version
$ cargo --version

Clone the published source and build a release binary. The first build may download locked dependencies.

git clone --branch v0.4.0-f4 --depth 1 https://github.com/galgo2077/VRG.git
cd VRG
cargo build --release --locked
test -x target/release/vrg
./target/release/vrg --help

This compiles from source. It is not a prebuilt download or a crates.io installation. When all dependencies are already cached, use cargo build --release --locked --offline.

Optional Cargo Git install (clean-machine verification pending)
cargo install --git https://github.com/galgo2077/VRG.git --tag v0.4.0-f4 --locked
vrg --help

This still compiles the source on your machine. If it fails, use the clone-and-build path above.

Official crates.io: version 0.1.1 verified on Void Linux x86_64.

cargo install vrg --locked
vrg --version

02 / SAFE FIRST RUN

Test without your vault.

Create an isolated sample root with one Markdown note. This command creates a unique temporary demo directory.

DEMO_BASE="$(mktemp -d /tmp/vrg-demo.XXXXXXXX)" || { echo "Cannot create demo directory" >&2; exit 1; }
mkdir "$DEMO_BASE/notes"
printf '# Demo\n\nThe blue zafiro compass is a synthetic test.\n' > "$DEMO_BASE/notes/demo.md"
DEMO_CFG="$DEMO_BASE/config.toml"
cat > "$DEMO_CFG" <<EOF
data_dir = "$DEMO_BASE/data"
capture_session_events = false

[[roots]]
id = "demo"
path = "$DEMO_BASE/notes"
allowed_files = ["demo.md"]
EOF
./target/release/vrg --config "$DEMO_CFG" status
./target/release/vrg --config "$DEMO_CFG" index
./target/release/vrg --config "$DEMO_CFG" search "zafiro compass" --root demo --text-only

Expect an attributed hit from demo.md, without modifying the source. The semantic model is optional: text-only search works without downloading model files. Use only synthetic files for rollback or destructive recovery tests.

03 / READ-ONLY MCP

Connect to Codex.

Make an isolated project-level .codex/config.toml and use your own absolute paths. Do not paste this placeholder config unchanged.

[mcp_servers.vrg]
command = "/absolute/path/to/VRG/target/release/vrg"
args = ["--config", "/absolute/path/to/demo.toml", "mcp", "serve"]
cwd = "/absolute/path/to/VRG"
enabled = true
required = true
enabled_tools = [
  "vrg_status", "vrg_search",
  "vrg_read_source", "vrg_graph_neighbors"
]

Launch a new Codex session; use /mcp, verify the four read-only tools and test vrg_status first. Only search or read content that you explicitly authorized. A remote Codex model may receive snippets from a local MCP server.

06 / TROUBLESHOOTING

Common issues.

cargo --offline fails

Dependencies are missing from the local Cargo cache. Perform a reviewed online build using the locked dependencies first.

VRG is absent from Codex /mcp

Verify the server command, effective project config, executable, startup output and allowlist. Existing sessions may retain an older process.

Hook shows modified or untrusted

Review and trust the current handler in /hooks; do not bypass or edit the trust store.

Model or semantic retrieval unavailable

Use text-only search, or provision and verify the optional multilingual-e5-small model and tokenizer artifacts separately.

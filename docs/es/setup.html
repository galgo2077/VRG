01 / INSTALACIÓN

Descarga la versión F4.

Necesitas Git, Rust + Cargo 1.92 o superior de la guía oficial de Rust ↗ y las herramientas de compilación necesarias. Void Linux fue el entorno local validado; otras plataformas requieren comprobación propia.

$ git --version
$ rustc --version
$ cargo --version

Clona el tag publicado y compílalo. La primera compilación puede descargar las dependencias fijadas.

git clone --branch v0.4.0-f4 --depth 1 https://github.com/galgo2077/VRG.git
cd VRG
cargo build --release --locked
test -x target/release/vrg
./target/release/vrg --help

Compilación desde código, no un ejecutable descargado ni una instalación crates.io. Con todo en caché: cargo build --release --locked --offline.

Alternativa Cargo Git (aún no verificada en un equipo limpio)
cargo install --git https://github.com/galgo2077/VRG.git --tag v0.4.0-f4 --locked
vrg --help

También compila el código fuente en tu máquina. Si falla, utiliza la ruta de clonación anterior.

02 / PRUEBA AISLADA

Prueba sin dar acceso a Obsidian.

Esta prueba crea una nota de demostración y una configuración aislada. Si ya existe la configuración, revísala antes de sobrescribir.

mkdir -p "$HOME/vrg-demo-notes" "$HOME/.config/vrg"
printf '# Demo\n\nLa brújula zafiro azul es una prueba sintética.\n' > "$HOME/vrg-demo-notes/demo.md"
DEMO_CFG="$HOME/.config/vrg/demo.toml"
if test -e "$DEMO_CFG"; then
  echo "Revisa demo.toml antes de continuar" >&2
else
  cat > "$DEMO_CFG" <<EOF
data_dir = "$HOME/.local/share/vrg-demo-derived"
capture_session_events = false

[[roots]]
id = "demo"
path = "$HOME/vrg-demo-notes"
allowed_files = ["demo.md"]
EOF
fi
./target/release/vrg --config "$DEMO_CFG" status
./target/release/vrg --config "$DEMO_CFG" index
./target/release/vrg --config "$DEMO_CFG" search "brújula zafiro" --root demo --text-only

Debe devolver un hit atribuido a demo.md y conservar intacta la fuente. No necesitas embeddings para la búsqueda textual. Los escenarios destructivos deben limitarse a este perfil sintético.

03 / MCP READ-ONLY

Conecta Codex.

Crea una configuración de proyecto .codex/config.toml con rutas absolutas reales. No pegues estas rutas de ejemplo sin reemplazarlas.

[mcp_servers.vrg]
command = "/ruta/absoluta/VRG/target/release/vrg"
args = ["--config", "/ruta/absoluta/demo.toml", "mcp", "serve"]
cwd = "/ruta/absoluta/VRG"
enabled = true
required = true
enabled_tools = [
  "vrg_status", "vrg_search",
  "vrg_read_source", "vrg_graph_neighbors"
]

Abre una sesión nueva y usa /mcp. Comprueba las cuatro herramientas y empieza por vrg_status. El modelo remoto de Codex puede recibir fragmentos devueltos por MCP; no compartas notas personales sin autorización.

04 / AUTOMATIZACIÓN OPCIONAL

Hooks y memoria compacta.

El release contiene examples/codex/hooks.json.example y scripts/vrg_hook_observer.py. El supervisor Unix portable no hereda la certificación del supervisor local original.

01
Revisa el script

Configura VRG_HOOK_EXECUTABLE y VRG_HOOK_EVIDENCE_DIR con rutas existentes y privadas.

02
Confía únicamente en definiciones revisadas

En /hooks examina SessionStart, UserPromptSubmit y Stop. La confianza es independiente de MCP.

03
Observa eventos reales

Prueba desde una sesión nueva; guarda solo metadatos acotados, no conversaciones completas.

VRG MCP es de solo lectura. Codex puede editar exclusivamente documentación Markdown autorizada con herramientas normales, y VRG indexa su revisión.

06 / SOLUCIÓN DE PROBLEMAS

Errores habituales.

Falla cargo --offline

Faltan dependencias en la caché. Obtén primero las dependencias fijadas mediante una compilación autorizada con red.

VRG no aparece en /mcp

Comprueba ejecutable, configuración efectiva del proyecto y allowlist.

Hook modified o untrusted

Revisa en /hooks la definición actual; no manipules el registro de confianza.

No hay búsqueda semántica

Usa búsqueda textual o instala un modelo local compatible y verificado.
